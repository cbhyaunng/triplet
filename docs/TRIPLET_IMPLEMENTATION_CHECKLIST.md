# TRIPLET Implementation Checklist

## 1. 목적

이 문서는 발표용 데모를 기준으로 `무엇을 먼저 만들고`, `어떤 순서로 붙이며`, `각 단계가 언제 끝난 것으로 볼지`를 정리한 구현 체크리스트다.

핵심 원칙은 아래와 같다.

- 먼저 `입력원`을 만든다.
- 그 다음 `수신기`를 붙인다.
- 그 다음 `지도/위치`를 연결한다.
- 마지막에 `발표용 UI와 시연 흐름`을 다듬는다.

즉, 구현 우선순위는 아래 순서다.

1. 테스트 알림 앱
2. 트립랫 listener
3. 위치 매칭
4. 지도/내역 UI
5. 통계/발표 리허설

## 2. 전체 단계 요약

| 단계 | 목표 | 우선순위 |
|---|---|---:|
| Phase 0 | 공통 규격 확정 | 최고 |
| Phase 1 | 테스트 알림 앱 MVP 완성 | 최고 |
| Phase 2 | 트립랫 listener 로 알림 수신 성공 | 최고 |
| Phase 3 | 여행모드 + 위치 샘플 저장 | 높음 |
| Phase 4 | 알림-위치 매칭 + 내역 저장 | 높음 |
| Phase 5 | 지도/내역/통계 화면 연결 | 중간 |
| Phase 6 | 발표 시연 시나리오 고정 | 최고 |
