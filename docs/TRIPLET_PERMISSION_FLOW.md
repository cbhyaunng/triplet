# TRIPLET Permission Flow

## 1. 목적

이 문서는 트립랫 안드로이드 앱에서 권한을 어떤 순서로, 어떤 화면에서, 어떤 설명과 함께 요청할지 정의한다.

권한의 핵심은 "처음부터 무조건 많이 받는 것"이 아니라, 사용자가 여행모드를 시작하는 맥락 안에서 필요한 권한을 단계적으로 받는 것이다.

## 2. MVP에서 사용하는 권한과 접근

## 2.1 시스템 권한 / 특수 접근

| 항목 | 유형 | MVP 사용 여부 | 목적 |
|---|---|---:|---|
| 알림 접근 권한 | 특수 접근 | 예 | 테스트 알림 앱이 보낸 결제 알림 읽기 |
| ACCESS_FINE_LOCATION | 런타임 권한 | 예 | 여행 중 위치 샘플 수집 |
| FOREGROUND_SERVICE | manifest | 예 | 여행모드 위치 추적 service |
| FOREGROUND_SERVICE_LOCATION | manifest | 예 | 위치 foreground service 타입 지정 |
| POST_NOTIFICATIONS | 런타임 권한 | 선택 | 우리 앱 안내 알림 표시 |
| ACCESS_BACKGROUND_LOCATION | 런타임 권한 | 아니오 | MVP에서는 기본 요구 안 함 |

## 2.2 요청하지 않는 것

- READ_SMS
- RECEIVE_SMS
- 전화/통화 관련 권한

## 3. 권한 요청 원칙

### 원칙 1. 여행모드 시작 맥락에서 요청

권한은 앱 설치 직후가 아니라, 사용자가 "이제 여행을 기록하겠다"는 의도를 보였을 때 요청한다.

### 원칙 2. 알림 접근과 위치 권한은 분리 요청

한 번에 모두 묶어 요청하면 거부율이 높아진다.

### 원칙 3. 거절해도 앱은 열리지만 핵심 기능은 제한

- 알림 접근 거절: 자동 결제 수집 불가
- 위치 권한 거절: 지도 자동 기록 불가

### 원칙 4. 거절 후 재시도 경로 제공

- 시스템 설정 이동 버튼
- 현재 권한 상태 설명
- 제한 모드 안내

## 4. 화면별 시나리오

## 4.1 SplashScreen

### 역할

- 로그인 상태 확인
- 현재 권한 상태 확인
- 활성 여행 존재 여부 확인

### 동작

- 앱 최초 실행이면 Onboarding 으로 이동
- 로그인 완료 후 활성 여행이 없으면 TripCreate 로 이동
- 활성 여행이 있고 여행모드가 켜져 있으면 Home 으로 이동하고 상태 배너 표시

### 이 화면에서는 직접 권한 요청하지 않음

이유:

- 앱 진입 직후 권한 팝업은 거부감이 크다.

## 4.2 OnboardingIntroScreen

### 사용자에게 보여줄 핵심 메시지

- 트립랫은 여행모드 중에만 결제와 위치를 연결한다.
- 자동 가계부를 만들기 위해 알림 접근과 위치 권한이 필요하다.
- 언제든 여행모드를 끄고 기록을 중단할 수 있다.

### CTA

- `여행 준비하기`

## 4.3 PermissionEducationScreen

이 화면은 시스템 팝업 전에 앱 자체 설명을 먼저 보여준다.

### 섹션 1. 알림 접근

- 왜 필요한가: 테스트용 결제 알림을 읽어 자동 가계부를 만들기 위해
- 수집 대상: 발표용 테스트 알림 앱이 생성한 결제 알림
- 제한 사항: 허용하지 않으면 수동 입력만 가능

### 섹션 2. 위치 권한

- 왜 필요한가: 결제 발생 위치를 지도에 표시하기 위해
- 언제 수집하는가: 여행모드 ON 상태에서만
- 허용하지 않으면: 소비 위치 및 경로 자동 기록 불가

### CTA

- `알림 접근 설정하기`
- `다음에 설정하기`

## 4.4 NotificationAccessScreen

### 진입 조건

- 사용자가 자동 수집 기능을 사용하려고 함
- 발표 데모에서는 테스트 알림 앱과 트립랫을 모두 설치해둔 상태

### 동작

1. 현재 알림 접근 상태 확인
2. 미허용이면 `Settings.ACTION_NOTIFICATION_LISTENER_SETTINGS` 로 이동
3. 사용자가 돌아오면 다시 상태 확인

### 성공 시

- LocationPermissionScreen 으로 이동

### 실패 시

- 홈으로 진입 가능
- 단, 홈 상단에 `자동 결제 수집이 비활성화됨` 배너 표시

## 4.5 LocationPermissionScreen

### 요청 권한

- `ACCESS_FINE_LOCATION`

### 요청 방식

- 앱 내부 설명 후 시스템 권한 요청

### 성공 시

- 여행 생성 또는 여행 시작 화면으로 이동

### 사용자가 대략 위치만 허용한 경우

- 홈 화면 진입은 허용
- `정확한 위치가 아니어서 매칭 정확도가 낮아질 수 있음` 배너 표시
- 자동 위치 매칭 confidence 를 보수적으로 낮춤

### 사용자가 거절한 경우

- 자동 결제는 계속 가능
- 위치 없는 소비 기록으로 저장
- 내역에서 수동 위치 지정 가능

## 4.6 TripCreateScreen

### 역할

- 여행 제목, 국가, 도시, 시작일 입력
- 여행 생성 후 여행모드 시작 여부 선택

### 권한과의 관계

- 이미 권한이 모두 있으면 바로 여행모드 시작 가능
- 부족한 권한이 있으면 start 버튼 아래 경고 문구 표시

## 4.7 TravelModeStartBottomSheet

이 화면이 실제 권한 흐름의 중심이다.

### 사용자 액션

- `여행모드 시작`

### 시작 전 체크

- 알림 접근 허용 여부
- 위치 권한 허용 여부
- 위치 서비스 켜짐 여부

### 모두 충족 시

- `TravelLocationService` 시작
- 활성 여행 상태를 `ACTIVE` 로 변경
- 상단 persistent notification 표시

### 일부 미충족 시

- 알림 미허용: `자동 결제 수집 없이 시작`
- 위치 미허용: `지도 기록 없이 시작`
- 둘 다 미허용: 여행모드 시작 자체는 가능하지만 수동 기록 모드로 안내

## 4.8 HomeScreen

### 상태 배너 규칙

- 알림 접근 없음: `자동 결제 수집 꺼짐`
- 위치 권한 없음: `위치 기록 꺼짐`
- 대략 위치만 허용: `위치 정확도 낮음`
- foreground service 비정상 종료: `여행모드가 중단됨. 다시 시작해 주세요`

### 빠른 액션

- 권한 재설정
- 위치 서비스 켜기
- 여행모드 재시작

## 4.9 LedgerScreen

### 역할

- 자동 수집된 내역 확인
- 수동 입력
- 위치 없는 내역 수정

### 권한 영향

- 위치 권한이 없으면 `지도에 표시할 수 없음` 상태를 명확히 보여줌
- 알림 접근이 없으면 `수동 입력` CTA를 더 강조

## 4.10 SettingsScreen

설정 화면은 권한 복구 허브 역할을 한다.

### 표시 항목

- 알림 접근 권한 상태
- 위치 권한 상태
- 위치 서비스 ON/OFF 상태
- 여행모드 상태

### 버튼

- `알림 접근 설정 열기`
- `앱 권한 설정 열기`
- `여행모드 다시 시작`

## 4.11 TripEndScreen

### 사용자 액션

- `여행 종료`

### 종료 시 수행

- 위치 foreground service 중단
- active trip 상태 변경
- 서버 동기화 실행
- 요약 리포트 생성

### 권한과의 관계

- 종료 자체는 권한과 무관
- 종료 후에는 위치를 더 이상 수집하지 않음

## 5. 권한 흐름 시나리오

## 시나리오 A. 이상적인 첫 설치 흐름

1. 온보딩 진입
2. 알림 접근 설명
3. 알림 접근 허용
4. 위치 권한 설명
5. 정확한 위치 허용
6. 여행 생성
7. 여행모드 시작
8. foreground service 시작

## 시나리오 B. 알림 접근 거절

1. 알림 접근 설정 화면 진입
2. 사용자가 허용하지 않고 돌아옴
3. 앱은 홈으로 진입 허용
4. 자동 수집 비활성 상태 배너 표시
5. 수동 입력 중심 UX 제공

## 시나리오 C. 위치 권한 거절

1. 위치 권한 요청
2. 사용자가 거절
3. 결제 알림은 계속 읽음
4. 지출은 생성되지만 좌표 없음
5. 사용자는 나중에 내역 상세에서 위치 수동 지정

## 시나리오 D. 대략 위치만 허용

1. 위치 권한 허용
2. OS가 coarse location 만 제공
3. 위치 기록은 가능하나 좌표 정확도 낮음
4. 자동 매칭 confidence 낮게 저장
5. 리뷰 필요 건 비율 증가 가능

## 시나리오 E. 여행모드 중 서비스 중단

원인 예시:

- 사용자 강제 종료
- 배터리 최적화
- 시스템 메모리 정리

대응:

- 앱 재진입 시 active trip 와 service 상태 비교
- 불일치하면 홈 상단에 경고 배너 표시
- `여행모드 다시 시작` 버튼 제공

## 6. UX 문구 예시

### 알림 접근 설명

`카드사 앱의 결제 알림을 읽어 자동으로 지출 내역을 기록합니다. 허용하지 않으면 수동 입력만 사용할 수 있습니다.`

### 위치 권한 설명

`여행모드가 켜진 동안 위치를 기록해 결제 위치를 지도에 표시합니다. 허용하지 않으면 소비 위치와 이동 경로 자동 기록이 제한됩니다.`

### 대략 위치 경고

`현재 대략 위치만 허용되어 있어 결제 위치가 정확하지 않을 수 있습니다.`

## 7. 구현 체크리스트

- Notification listener 접근 상태 체크 함수 구현
- 위치 권한 상태 체크 함수 구현
- 위치 서비스 ON/OFF 체크 함수 구현
- foreground service 실행 상태 체크 함수 구현
- 권한 거절 후 설정 이동 딥링크 구현
- 여행모드 시작 시점에만 location service 시작
- 대략 위치/정확한 위치 분기 처리
- 테스트 알림 앱이 설치되어 있는지 체크하는 헬퍼 구현
- allowlist 패키지명이 기대값과 일치하는지 로그로 확인

## 8. 주의사항

- MVP에서는 `ACCESS_BACKGROUND_LOCATION`을 기본 전제로 두지 않는다.
- 위치 foreground service 는 사용자가 앱이 보이는 상태에서 시작해야 한다.
- 권한을 받았다고 해도 사용자가 OS 설정에서 나중에 언제든 회수할 수 있으므로 매 진입 시 상태 재확인이 필요하다.
- 테스트 알림 앱은 Android 13 이상에서 알림 발송을 위해 `POST_NOTIFICATIONS` 권한이 필요하다.
